## Summary
The most realistic acceptance hole is quoted or echoed handoff text inside an assistant turn. Searching only assistant turns prevents Orbit from collecting its own user-side assignment, but it does not establish that a matching block in an assistant turn was intended as the return artifact. A worker can quote a previous handoff, repeat the assignment while discussing it, or show a corrected example. If that later assistant text contains a complete block with the expected filename and a valid header, "newest wins" can cause the quotation or example to be accepted instead of the intended handoff. Transcript collection should require one unambiguous top-level envelope in the designated return turn, rather than accepting any matching string found inside assistant prose.
Code fences, quotations, and examples are another realistic form of the same problem. The described parser operates on flattened transcript text and does not say that fenced or quoted regions are excluded. An assistant explaining the protocol could therefore emit literal BEGIN and END lines inside an example and accidentally create a valid candidate. If the accessibility representation cannot reliably preserve Markdown context, a practical rule is that the BEGIN line must be the first non-empty top-level text of the eligible assistant turn and the END line must be its last non-empty top-level text. Competing or embedded candidates should make collection fail closed.
"Newest wins" is weaker than the file-artifact path and can be abused accidentally or deliberately. A downloadable artifact card is a discrete object selected by filename. Transcript text has no equally strong artifact boundary. A later assistant turn may contain a correction, quotation, summary, or second complete candidate with the same expected name. Recency proves only that the text came later, not that it is the intended authoritative handoff. The safer rule is "exactly one eligible candidate in the expected return turn." If there are two complete eligible blocks, Orbit should report ambiguity instead of silently selecting the newest.
Nested, overlapping, or body-embedded marker text can alter boundaries while still leaving enough valid metadata for acceptance. For example, if the handoff body discusses the protocol and contains a line equal to ORBIT_HANDOFF_END, a simple first-END parser can truncate the body after a still-valid header. Validation can then succeed even though findings were lost. Multiple BEGIN lines before an END create similar ambiguity. Marker tokens should therefore be forbidden inside the body, and nested, overlapping, or multiply delimited candidates should be rejected rather than recovered heuristically.
Accessibility-tree transformation can corrupt unvalidated body content without causing the validator to fail. The stated inline-code header failure is one known example, but flattened accessibility text can also normalize whitespace, lose Markdown structure, split or merge text runs, omit formatting boundaries, lose link destinations, duplicate adjacent text, or reorder nearby rendered nodes depending on the UIA representation. Damage to required header lines, the work item, sender, or expected marker name will usually fail closed. Damage confined to Findings can still pass, including missing paragraphs, altered indentation, lost code formatting, duplicated prose, body truncation after a valid header, or link-target loss. The transcript collector therefore needs body/envelope structural checks in addition to the shared file validator.
Deleting an invalid reconstructed body is correct for the accepted inbox but wrong for diagnostics. An invalid candidate must not remain where another workflow component could mistake it for authority. However, deleting the only reconstructed copy destroys useful evidence about whether the worker emitted malformed text or the accessibility bridge corrupted it. The better behavior is to remove or never place it in the authoritative inbox while preserving a quarantined diagnostic copy with the validation reason, collection time, expected filename, chat identity, and source turn locator. Quarantine must carry no workflow authority.
The transcript path needs stronger provenance correlation than the file path. Orbit verifies the active-chat header before reading, which is good, but the reconstructed file itself does not appear to retain which assistant turn supplied it or how many competing candidates were present. A stale or ambiguous transcript tail is therefore harder to audit after collection. Collection metadata should record the verified chat identity, assistant-turn position or stable locator if available, candidate count, and collection timestamp outside the handoff contract.
Based on the stated design, the post-extraction validator is not obviously missing a file-path validation rule: the transcript body is written under the expected filename and then goes through the same filename, work-item, Header, header-work-item, and expected-sender checks, while ZIP is refused entirely. The important missing checks live before that validator. The file path begins with a discrete artifact object; the transcript path must infer artifact intent, boundaries, and fidelity from conversation text. Those transport-specific properties need explicit validation before anything is admitted to the inbox.
Highest-Priority Gap: Replace unrestricted "newest matching block wins" with an unambiguous single-envelope rule. A realistic assistant can easily quote, echo, revise, or demonstrate a handoff later in the conversation, and all of those appear inside assistant turns, so assistant-turn filtering alone does not prove intent. Require exactly one eligible block in the designated return assistant turn, with BEGIN as the first non-empty envelope line and END as the last, and reject additional matching blocks, nested markers, body marker lines, or examples that cannot be distinguished from top-level output. This most directly makes transcript collection behave like selecting one discrete artifact rather than searching a conversation for whichever matching text happened to appear last.
